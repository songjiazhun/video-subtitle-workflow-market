# 字幕优化规则（阶段 2 专用）

对照原稿 `origin.md` 修正 `origin.srt`，输出 `enhanced.srt`。
**这一步必须由模型逐条阅读判断，禁止写脚本批量替换**——正则无法理解语义，
会把正确内容改错。

## 铁律

| 项目 | 要求 |
| --- | --- |
| 时间戳 | 一个字符都不能改 |
| 条目数 | 必须与输入完全一致，不合并、不拆分、不删除 |
| 序号 | 保持连续且与原文对应 |
| 内容来源 | 只修正 SRT 里已有的内容，**不得**把原稿里有、字幕里没有的句子补进来 |
| 语义 | 不改写句式、不润色语气，只纠错 |

改完必须跑校验：

```bash
python3 scripts/srt_utils.py verify origin.srt enhanced.srt
```

## 修正范围（按优先级）

### 1. 影响理解的错别字

以 `origin.md` 为准。同音字错误是语音识别的重灾区。

```
工俱 → 工具        在座 → 再做        帐号 → 账号
以经 → 已经        既然 → 即然（反向也要判断哪个才对）
```

判断依据是原稿，不是模型的语感。原稿里没提到的词，除非明显是同音字错误，
否则保持原样。

### 2. 专有名词统一

原稿写 `Next.js` 就不能出现 `NextJS` / `next js` / `Nextjs`。
人名、产品名、技术栈名一律以原稿拼写为准，包括大小写和点号。

常见识别错误：

```
派森 → Python           瑞艾克特 → React
够语言 → Go 语言        道克 → Docker
```

### 3. 中英文/数字之间加半角空格

这是排版规范（俗称「盘古之白」），也是最常触发的一条。

**要加空格：**

```
今天要介紹Python3.9的新功能   →  今天要介绍 Python 3.9 的新功能
總共有3個步驟                 →  总共有 3 个步骤
用React寫前端                 →  用 React 写前端
CPU使用率到80%                →  CPU 使用率到 80%
```

**不要加空格：**

| 场景 | 正确写法 | 说明 |
| --- | --- | --- |
| 英文短语内部 | `machine learning` | 本来就有空格，别再插 |
| 数字内部 | `123,456`、`3.14` | 千分位和小数点不拆 |
| 中文标点相邻 | `使用 Python，然后……` | 标点与中文之间不加 |
| 版本号 | `Python 3.9` | 数字与点号是一体的 |
| 已有空格 | — | 不要变成两个空格 |
| 全角括号内 | `（Python）` | 括号紧贴内容 |

单位与数字之间按原稿习惯处理，原稿写 `80%` 就别改成 `80 %`。

### 4. 标点补全

语音识别常整段无标点。可以补句读，但**不要**因此改变断句语义。
一条字幕内部原则上不超过一个句末标点。

## 语义匹配方法

原稿是书面语，字幕是口语转写，两者不会逐字对应。匹配时：

- 按**段落主题**定位，而不是逐字符比对
- 口头禅、语气词（「那个」「就是说」「呃」）在原稿里不会有，**保留**，不要删
- 原稿有而字幕没有的整句，说明讲者临场跳过了，**不要补**
- 一句话被拆到多条字幕里很正常，跨条判断上下文

## 拿不准的情况

| 情况 | 处理 |
| --- | --- |
| 原稿里找不到对应内容 | 只套用空格规则，其余保持原样 |
| 两种改法都说得通 | 选改动更小的那个 |
| 疑似错别字但原稿未涉及 | 保持原样，不要猜 |
| 字幕明显比原稿多出内容 | 保留，这是讲者即兴发挥 |

保守优先。改错的代价远大于漏改。

## 完整示例

**origin.md**

```markdown
今天要介绍 Python 3.9 的新功能。首先是 match case 语句，这是一个强大的模式匹配工具。
```

**origin.srt**

```
1
00:00:00,000 --> 00:00:05,000
今天要介紹Python3.9的新功能

2
00:00:05,000 --> 00:00:10,000
那個首先是match case語句這是一個強大的模式匹配工俱
```

**enhanced.srt**

```
1
00:00:00,000 --> 00:00:05,000
今天要介绍 Python 3.9 的新功能

2
00:00:05,000 --> 00:00:10,000
那个首先是 match case 语句，这是一个强大的模式匹配工具
```

改动清单：

- `Python3.9` → `Python 3.9`（加空格）
- `match case` 前后加空格
- `工俱` → `工具`（对照原稿纠错）
- 补一个逗号断句
- **保留**「那个」这个口头禅——原稿没有，但讲者确实说了
- 时间戳、序号、条数完全未动
